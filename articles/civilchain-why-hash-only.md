## ブロックチェーンの不変性は諸刃の剣

ブロックチェーンの最大の特性は「一度記録したデータを改ざんできない」ことです。これは公的記録の信頼性を担保する上で非常に強力な性質です。

しかし裏を返すと、**一度入れてしまったデータは削除できない**ということでもあります。

## 入ってはいけない情報がある

ブロックチェーンに直接記録してはいけない情報があります。

- **虚偽の情報** — 誤った記録が永遠に残る
- **個人情報** — 削除できないため、プライバシー上の問題になる
- **著作権を侵害するコンテンツ** — 権利者が削除を要求しても対応できない

これらを平文でブロックチェーンに入れてしまうと、取り消す手段がありません。

## 解決策：ハッシュ値のみを記録する

CivilChainでは、ブロックの `Data` フィールドに**SHA-256ハッシュ値のみ**を保存するとしました。

ハッシュ値は元データの「指紋」です。元データを復元することはできません。そのため、ハッシュ値自体がチェーンに残っていても、平文の情報が漏れることはありません。

## CivilChain と CivilHub の役割分担

平文データの保存先として、**CivilHub**という別のデータベースを用意する設計にしています。

| | CivilChain | CivilHub |
|---|---|---|
| 保存するもの | ハッシュ値 | 平文データ |
| 改ざん | 不可能 | 可能（管理者が削除・修正できる） |
| 役割 | 改ざん検知 | データ管理 |

検証の流れはこうなります。

1. データを登録するとき — クライアントが平文データをハッシュ化し、CivilChainにPoWでハッシュ値を記録する。その後、CivilHubに平文データを登録する。
2. 検証するとき — CivilHubの平文データをハッシュ化し、CivilChainのハッシュ値と比較する。一致すれば改ざんされていないことが確認できる。

問題のある平文データはCivilHubから削除できます。チェーン上にはハッシュ値だけが残りますが、元データがなければ意味をなしません。

## 実装：isValidHash() で入口を守る

CivilChainのHTTPノードでは、`POST /block` でブロックを追加する際に `isValidHash()` でバリデーションをかけています。

```go
func isValidHash(data string) bool {
    if len(data) != 64 {
        return false
    }
    for _, c := range data {
        if !((c >= '0' && c <= '9') || (c >= 'a' && c <= 'f')) {
            return false
        }
    }
    return true
}
```

SHA-256のハッシュ値は64文字の16進数文字列（`0`〜`9`、`a`〜`f`）です。この形式以外のデータは `400 Bad Request` で弾きます。

```go
if !isValidHash(string(body)) {
    http.Error(w, "データはSHA-256ハッシュ値である必要があります", http.StatusBadRequest)
    return
}
```

## おわりに

「なぜハッシュ値のみを保存するのか」という設計の根拠は、最初に固めておく必要がありました。ノード間の通信やCivilHubの実装はこれからですが、データの扱い方は、この段階で整理しておく必要がありました。
